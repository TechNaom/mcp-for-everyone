Chapter 12 Project ~35 min · Level 2, Assisted

Build a Dual-Era Behavior-Parity Checker

The exact test this chapter's senior interview question described — built, and proven to actually catch a real mismatch, not just report "PASS" trivially.

Runs the same tool calls against a server under both mode="auto" (modern) and mode="legacy", and flags any call whose result differs — this chapter's central finding (dual-era support is automatic, behavior parity is not) made into a reusable regression test.

starter.py solution.py (reference)

Build it

Implement run_calls (execute a list of tool calls, recording results) and check_parity (run the same calls under both eras and compare). Test against Chapter 12's exercises server, which behaves identically across eras — you should see a clean PASS.

Verification 
python solution.py
Expect: PASS: identical behavior across modern and legacy eras.
Extension challenge — prove it actually works Write a small, deliberately buggy server whose tool returns a different value on each call (e.g. an internal counter). Run your checker against it and confirm it correctly reports a mismatch — don't just trust that your checker passes when it should; confirm it fails when it should too, the same discipline used throughout this course.

Why this project matters

A parity checker that only ever reports PASS isn't actually testing anything — the extension challenge exists specifically to make sure you've built a real check, not a check that trivially always succeeds. This mirrors exactly how this chapter's own lesson content was validated while being written.
