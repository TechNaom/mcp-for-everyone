Chapter 12 Exercises ~25 min

Exercises: Versioning, Errors & Production Hardening

Confirm dual-era behavior yourself, then harden a tool against a simulated dependency failure.

How to run these 
pip install "mcp[cli]"
cd chapters/chapter-12-versioning-errors-production-hardening/exercises
python solution.py   # or fill starter.py first
starter.py solution.py (reference)

1 (Production-gear) Simulate a dependency failure

Implement fetch_user_count per TODO 1, raising a clear error when _SIMULATE_DB_DOWN is True.

2 Confirm dual-era support yourself

Implement confirm_dual_era per TODO 2. Confirm the two protocol versions differ, exactly as the lesson showed.

3 (Production-gear) Confirm validation errors

Implement confirm_validation_errors per TODO 3.

4 (Production-gear) Confirm dependency-failure handling

Implement confirm_dependency_failure per TODO 4.

5 Test behavior parity across eras

Call add with the same valid arguments under both mode="auto" and mode="legacy". Confirm the result is identical — this is exactly the behavior-parity test this chapter's senior interview question described.

6 (Production-gear) Add a timeout-protected tool

Add a tool that simulates a slow dependency (use time.sleep briefly inside it), then write a client-side call wrapped in asyncio.wait_for with a short timeout, per Chapter 6's pattern. Confirm the timeout actually triggers.
