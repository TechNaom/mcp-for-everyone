Chapter 1 Exercises ~20 min

Exercises: The Integration Problem MCP Solves

This chapter is conceptual — no code yet, that starts in Chapter 4. These exercises build the judgment you'll need before you write a single tool.

1 Count the integrations

An org has 8 internal tools and 3 AI surfaces that need them. Calculate the bespoke integration count (N×M) versus the shared-protocol count (N+M). Write one sentence on what the gap represents in practice.

2 Spot the trap

Reread the "bespoke-integration trap" section. Name a real or hypothetical example from your own work (or a plausible one) where the same logic got reimplemented in more than one place and drifted apart. What was the actual cost when it drifted?

3 (Production-gear) The one-consumer test

List three tools you might build for an AI assistant. For each, decide: does it have (or will it soon have) more than one consumer? Which ones would you build as a direct function call today, and which would you build as an MCP server from day one, and why?

4 (Production-gear) Security isn't included

Take one tool from Exercise 3 that you'd expose over MCP. Name one thing that could go wrong if that tool is over-permissioned — and explain why moving it to MCP does not, by itself, fix that risk.

5 (Production-gear) The migration call

A company has 12 bespoke tool integrations across 3 products, no MCP yet. You have budget to migrate 3 of them this quarter. Given only "reuse count" as your ranking criterion, describe how you'd decide which 3 to migrate first — and what additional information you'd want before finalizing that list.

6 Explain it to a skeptic

Write a 3-sentence explanation of why MCP exists, aimed at a engineer who says "isn't this just function calling with extra steps?" Your explanation must include the word "reuse" and must not use the word "standard" as a substitute for actually explaining the problem.
