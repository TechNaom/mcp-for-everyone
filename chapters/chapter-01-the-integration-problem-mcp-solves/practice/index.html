Chapter 1 Practice Bank ~20 min

Practice Bank: The Integration Problem MCP Solves

Scenario-based judgment calls — deciding when standardization is worth it, not just defining terms.

Scenario · Product

The eager adopter

A startup with one product and one AI feature wants to build "MCP-first" from day one, before they have a second consumer. What do you tell them about the trade-off they're making?

Scenario · Cost

The hidden fourth integration

A team counts 3 consumers for a tool and decides bespoke integration is still cheaper than standardizing. Two months later, a 4th consumer appears unexpectedly. What does this suggest about how "expected consumer count" should be estimated for this kind of decision?

Scenario · Compliance

The audit question

A compliance team asks: "if we standardize our tools behind MCP, does that make our AI system more auditable?" What's true and what's not true about this claim?

Scenario · Support

The bug that only showed up in one copy

Three bespoke copies of an order-lookup function exist. A bug is fixed in one, and a support engineer assumes it's fixed everywhere. It isn't. How does this scenario connect to the "bespoke-integration trap" from the lesson, and what specifically would have prevented it?

Scenario · Evaluation

The "reuse" that wasn't

A team migrates a tool to MCP anticipating three future consumers. Eighteen months later, only the original consumer ever used it. Was the decision wrong at the time it was made? How would you evaluate that, separate from how it turned out?

Scenario · Cost

The estimate that ignored operations

Someone calculates "N+M integrations instead of N×M" and concludes MCP is strictly cheaper. What ongoing cost does this calculation leave out (hint: something has to run and be maintained on the server side that didn't exist before)?
