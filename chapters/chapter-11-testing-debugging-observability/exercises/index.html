Chapter 11 Exercises ~25 min

Exercises: Testing, Debugging & Observability

Add structured, trace-correlated logging to the notes server, then use it to answer a "what happened" question the way this chapter's debugging workflow describes.

How to run these 
pip install "mcp[cli]"
cd chapters/chapter-11-testing-debugging-observability/exercises
python solution.py   # or fill starter.py first
starter.py solution.py (reference)

1 Add logging to save_note

Add Context and start/end structured log events to save_note, per TODO 1.

2 (Production-gear) Log failures too

Add the same to delete_note, per TODO 2 — including logging a tool_call_end event with is_error=True BEFORE raising the exception, so even a failed call leaves a trail.

3 (Production-gear) Build the trace filter

Implement find_calls_for_trace per TODO 3 — the core of the debugging workflow this chapter describes.

4 (Production-gear) Reconstruct an incident

Simulate three interleaved trace IDs' worth of log lines (at least 2 events each), mixed together in one list. Use your trace filter to reconstruct the full sequence of events for just one of them — the exact task a support engineer would do with real logs.

5 Combine with Chapter 10's firewall

Add a hit_count field to your structured logs, the way Chapter 10's ContentFirewall logged scan results. What would it look like to have ONE unified logging function used by both chapters' patterns, instead of two similar-but-separate ones?

6 (Production-gear) Redact a sensitive field

Add a body field to your save_note logging, but hash it (e.g. with hashlib.sha256) rather than logging it verbatim — per this chapter's interview question about logging sensitive tool arguments.
