Chapter 11 Project ~35 min · Level 2, Assisted

Build an SLO Calculator

Turn structured logs into the actual measurable SLOs this chapter's architect interview question asked about — success rate and p95 latency, per tool.

This project generates real traffic against the notes server (10 successful saves, 1 deliberate failure), captures its structured logs as they're actually emitted, and computes statistics from them — not from synthetic pre-written log lines. The logging pattern from this chapter's exercises is the entire foundation; this project is proof that it's enough to build a real dashboard on.

starter.py solution.py (reference)

Build it

Implement compute_slo_report: parse tool_call_end events, group by tool, and compute call count, success rate, and p95 latency for each. Then print_report to display it cleanly.

Verification 
python solution.py
Expect (after the raw log lines): 
save_note: 10 calls, 100.0% success, p95=0.10ms
delete_note: 1 calls, 0.0% success, p95=0.09ms
Extension challenge Add a --alert-threshold concept: if any tool's success rate drops below 95%, print a clearly-marked ALERT line. This is the first step from "dashboard" to "paging system" that this chapter's architect interview question distinguished.

Why this project matters

Logging that can't be turned into a metric isn't really observability yet — it's just text nobody reads until something breaks. This project closes that loop: the exact logging pattern from the exercises becomes real, computed operational numbers.
