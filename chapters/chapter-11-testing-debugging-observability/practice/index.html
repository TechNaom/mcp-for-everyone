Chapter 11 Practice Bank ~20 min

Practice Bank: Testing, Debugging & Observability

Operational judgment for a capability that only proves its worth during an incident.

Scenario · Operations

The deprecated dependency

A server built two years ago relies heavily on ctx.info() for its entire logging strategy. How would you plan a migration to standard logging without a risky big-bang rewrite?

Scenario · Cost

The logging bill

A team logs every tool call's full arguments and results at high volume, and their log aggregation bill triples. What would you cut first, and what would you never cut regardless of cost?

Scenario · Support

The trace ID nobody propagated

A user reports an issue. Support has a timestamp but no trace ID, because the host never generated or propagated one. What's the cheapest fix that would prevent this gap for the next incident?

Scenario · Debugging

The log that lied

A structured log shows is_error: false for a call the user insists failed. Given Chapter 4's lesson that a tool can return a "successful" result containing wrong data, what's your hypothesis, and how would logging alone not be enough to resolve it?

Scenario · Compliance

The retention question

Legal asks how long tool-call logs (potentially containing user data) should be retained. What factors would you weigh, and who should actually own this decision?

Scenario · Eval

The metric nobody's watching

A team has comprehensive structured logging but no dashboards or alerts built on it — an incident happened and was only found from a user complaint, days later, even though the logs clearly showed it. What's missing beyond "having the logs"?
