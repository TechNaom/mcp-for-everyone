Chapter 5 Project ~30 min · Level 1, Guided

Extend the Bookmarks Server

Add a static resource and a prompt to Chapter 4's bookmarks server — practice choosing the right primitive on a system you already know.

This reuses Chapter 4's bookmarks server rather than duplicating it, loaded by explicit file path (see the solution's _load_chapter_4_module helper) rather than a fragile sys.path trick — both files are named solution.py, and a naive import approach breaks depending on how the script is invoked. Worth reading that helper's docstring even if you don't touch it.

starter.py solution.py (reference)

Build it

Add bookmarks://count as a static resource returning a bookmark count, and recommend_reading(topic) as a prompt asking the model to recommend a relevant saved bookmark. The prompt should return instruction text only — it can't see the actual bookmark data itself; that's the host's job to supply alongside it.

Verification 
python -c "
import asyncio
from mcp import Client
from solution import mcp

async def main():
    async with Client(mcp) as client:
        await client.call_tool('add_bookmark', {
            'url': 'https://modelcontextprotocol.io',
            'title': 'MCP Docs', 'tags': ['mcp'],
        })
        r = await client.read_resource('bookmarks://count')
        print(r.contents[0].text)
        p = await client.get_prompt('recommend_reading', {'topic': 'protocols'})
        print(p.messages[0].content.text)

asyncio.run(main())
"
Expect 1 bookmarks, then the recommendation prompt text.
Extension challenge Add a second static resource, bookmarks://tags, that returns every unique tag across all saved bookmarks. Then decide: at what bookmark count would you reconsider this as a templated resource or a tool instead, per this chapter's scale discussion?

Why this project matters

Real MCP servers grow by accretion — a tool here, a resource there, added by whoever needs the next capability. Practicing on a system you already understand (rather than a fresh one) mirrors how this actually happens: you're extending, not starting over.
