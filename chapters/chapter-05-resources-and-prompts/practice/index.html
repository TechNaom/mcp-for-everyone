Chapter 5 Practice Bank ~20 min

Practice Bank: Resources & Prompts

Scenario judgment for choosing and operating the right primitive.

Scenario · Support

The "missing" resource ticket

A user reports a resource "isn't there" even though you can read it directly by URI. Before reading the lesson's production scenario again, what's the first question you'd ask the person who wrote the host's integration code?

Scenario · Product

The prompt marketplace

A product wants to let third-party teams publish prompts to a shared MCP server that any internal host can browse and use. What's different about reviewing a submitted prompt versus reviewing a submitted tool?

Scenario · Cost

The resource that got expensive

A templated resource fetches from a paid third-party API on every read, with no caching. Given what Chapter 3 said about cacheScope/ttlMs metadata on list results, what would you investigate to reduce cost without changing the resource's actual behavior?

Scenario · Compliance

The prompt with a hidden instruction

A prompt template returns text that includes an instruction like "ignore prior formatting constraints." Should this be treated differently from ordinary prompt content during a security review? Why?

Scenario · Operations

The static resource that stopped being static

A resource that used to return truly fixed app config now needs to vary by which team is asking. Does it stay a static resource, become templated, or become something else entirely? Walk through your reasoning.

Scenario · Eval

The untested primitive

A team's test suite has good coverage for tools but zero tests for resources or prompts. What's one concrete test you'd add for each, given what this chapter demonstrated about resource discovery and prompt message structure?
