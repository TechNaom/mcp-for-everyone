Chapter 2 Exercises ~20 min

Exercises: MCP Architecture

Practice mapping the host/client/server roles onto real systems — including ones this course hasn't shown you the internals of yet.

1 Label the roles

You use an AI coding assistant in your IDE that can read files, run tests, and search the web. Identify which piece is the host, and name at least two things that are plausibly separate MCP servers.

2 Count the clients

If that IDE assistant connects to 4 different servers (filesystem, test runner, web search, git), how many client connections does the host run? Draw or describe the diagram.

3 Find the model

In your diagram from Exercise 2, where does the LLM go? Explain in one sentence why it isn't drawn as a fourth role alongside host, client, and server.

4 (Production-gear) Name the owner

Revisit the retail inventory-server scenario from the lesson. If you were setting up this system from scratch, what would you put in place on day one — before any second consumer shows up — to avoid the ownership ambiguity that caused friction?

5 (Production-gear) The tool-name collision

A host connects to two servers that both expose a tool named search. This isn't a hypothetical — it will happen once an org has more than a couple of servers. Propose one concrete way a host could disambiguate between them for the model.

6 (Production-gear) The silent server

One of the four servers from Exercise 2 crashes mid-conversation. What should happen to the other three client connections? Should the whole host session fail, or should it degrade gracefully? Justify your answer in terms of the independence the architecture is supposed to provide.
