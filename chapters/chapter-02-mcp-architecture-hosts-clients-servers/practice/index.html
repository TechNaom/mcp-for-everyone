Chapter 2 Practice Bank ~20 min

Practice Bank: MCP Architecture

Realistic situations that test whether the host/client/server model is actually load-bearing in your thinking, not just memorized.

Scenario · Support

The confused bug report

A user files a bug: "the MCP server is slow." Turns out the actual latency is in the host's UI rendering, not any server response. What question would you ask first to figure out where in the host/client/server chain the slowness actually is?

Scenario · Product

The "add MCP support" feature request

A product manager asks engineering to "add MCP support to our app." Is the app becoming a host, a server, or could it be either depending on the feature? What follow-up question resolves the ambiguity?

Scenario · Cost

The always-on server

A team builds an MCP server that needs to stay running as a long-lived process to serve multiple hosts over Streamable HTTP, unlike the on-demand stdio server from Chapter 4 that only runs while a host has it open. What operational cost does this introduce that the Chapter 4 example didn't have?

Scenario · Compliance

The data residency question

Legal asks: "if our host connects to a third-party MCP server, does customer data pass through that server?" Using the host/client/server model, explain what actually flows between host and server during a tool call, so legal can answer their own question accurately.

Scenario · Operations

The multi-host server

Your team's inventory server (from the lesson) now has 5 host consumers, not 2. One of them wants a breaking schema change. Sketch, in a few sentences, a rollout approach that doesn't break the other 4 hosts on day one.

Scenario · Debugging

The wrong mental model

A new engineer on your team keeps referring to "the MCP" as if it's a single running thing, rather than a protocol multiple independent processes speak. What's one concrete example you'd show them to correct this — something they could observe, not just be told?
