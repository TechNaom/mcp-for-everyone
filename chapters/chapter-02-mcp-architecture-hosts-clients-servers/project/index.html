Chapter 2 Project ~30 min · Level 1, Guided

Diagram a Multi-Server Host Setup

Draw the architecture for a real (or realistic) product, then pressure-test it with the questions below.

Pick a product idea — a personal assistant, a support tool, a coding helper, anything. It needs to reach at least 3 different capabilities (data sources or actions) that don't naturally belong in the same server.

Build it

Produce a diagram (ASCII, like the lesson's, or a Mermaid sequence/architecture diagram if you prefer) showing:

  • One host box.
  • One client connection per server (at least 3).
  • Each server, labeled with what it exposes.
  • Where the model sits relative to all of this — and a one-sentence caption explaining why it isn't drawn as a fourth protocol role.
Verification Answer these about your own diagram: (1) if server #2 crashes, does your host still function for servers #1 and #3? (2) which server, if any, would you expect a second product to reuse unmodified? (3) who would own that reused server once a second product depends on it? If you can't answer all three from your diagram alone, the diagram is missing information a real design doc would need.
Extension challenge Two of your three servers both expose a tool with the same name. Add a note to your diagram showing how the host disambiguates them for the model (see Exercise 5 from this chapter's exercises).

Why this project matters

Every chapter from here forward assumes you can read and draw this kind of diagram fluently — Module 4's client/host chapters and Module 7's capstone both build directly on this skill. Getting comfortable with it now, on a simple example, pays off later on a much more complex one.
