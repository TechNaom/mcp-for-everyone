Chapter 7 Practice Bank ~20 min

Practice Bank: Building an MCP Client/Host

Judgment calls for the application-layer decisions MCP itself doesn't make for you.

Scenario · Support

The confusing success message

A user reports "I asked it to delete a note and it said it worked, but the note is still there." Walk through, in order, what you'd check in the host's code, referencing this chapter's most common bug pattern.

Scenario · Product

The impatient decision-maker

Your real (LLM-based) decision step takes 3 seconds to choose a tool, and users complain the assistant feels slow. Is this an MCP problem? What layer of the system does this delay actually belong to?

Scenario · Cost

The catalog re-fetch on every message

A host re-calls list_tools() before every single decision, even within the same ongoing conversation. What's the cost of this, and is there ever a good reason to actually do it anyway?

Scenario · Debugging

The host that hangs

A host occasionally hangs indefinitely after a tool call. Given Chapter 6's health-check project already solved a similar problem for server monitoring, what's the equivalent fix for the host's own tool invocation code?

Scenario · Compliance

The audit trail gap

Legal asks for a record of every tool call a host made on behalf of users over the past month. What would you need to have been logging from day one to answer this, and what should NOT be in that log by default (revisit this chapter's interview question 6)?

Scenario · Operations

The silent catalog change

A server's owning team removes a tool the host's cached catalog still lists. The host tries to call it and gets a clean is_error=True — but from the user's perspective, a previously-working feature just started failing with no warning. What operational practice would surface this proactively instead of waiting for a user to hit it?
