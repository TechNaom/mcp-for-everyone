Exercises: Building an MCP Client/Host

Extend ToyHost with argument support and defensive checks — the kind of hardening a toy example needs before it's trustworthy.

How to run these 
pip install "mcp[cli]"
cd chapters/chapter-07-building-an-mcp-client-host/exercises
python solution.py   # or fill starter.py first
starter.py solution.py (reference)

1 Add argument support

Implement handle_with_args per TODO 1, so save_note and other argument-taking tools actually work through the host.

2 (Production-gear) Guard against missing discovery

Implement TODO 2: refuse to call any tool if discover() hasn't run yet, with a clear message instead of a confusing failure.

3 (Production-gear) Test the typo path

Confirm a misspelled command produces a clear message, not a raw exception, per TODO 3.

4 (Production-gear) Add a call counter

Add a self.call_count attribute to ToyHost that increments on every successful tool call (not failed ones). This is the simplest possible building block for the observability content in Module 6 — notice how little code it takes to start building real operational visibility.

5 Swap in a smarter decision rule

Replace the exact-match lookup in handle_with_args with a rule that also matches if the command is a case-insensitive match, or a unique prefix of exactly one known tool name (e.g. "sav" uniquely matches "save_note"). What should happen if a prefix matches more than one tool?

6 (Production-gear) Handle a slow tool

Using the same asyncio.wait_for pattern from Chapter 6's health-check project, add a timeout to handle_with_args's tool call so a hung tool can't hang the whole host.
