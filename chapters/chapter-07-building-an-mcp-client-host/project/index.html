Chapter 7 Project ~40 min · Level 1, Guided

Build a Command-Line Host

A real, usable host — type commands, they run against a live MCP server. This is ToyHost grown into something you'd actually use.

Every host in this course so far has been driven by test code you wrote. This one is driven by you, typing at a terminal — the closest this course gets to what using an MCP-connected assistant actually feels like, minus the model.

starter.py solution.py (reference)

Build it

Implement CLIHost.run_line: parse a line like save_note title="todo" body="buy milk" into a tool name and arguments (the parse_line helper is provided), look it up against the discovered catalog, call it, and check is_error — the same discipline as every host in this course. Then wire up the stdin loop in main().

Verification 
printf 'save_note title="todo" body="buy milk"\nlist_notes\nquit\n' | python solution.py
Expect: 
Ready. Known commands: ['save_note', 'list_notes', 'delete_note', 'search_notes', 'note_count', 'rename_note']
{'result': "Saved note 'todo' (8 characters)."}
{'result': ['todo']}
Also try an unknown command and confirm you get a clear message, not a crash.
Extension challenge Add a help command that prints each known tool's name and its description (available on the objects list_tools() returns) — the beginning of real discoverability for a human user, not just a model.

Why this project matters

This project makes tangible what "a host" means after six chapters of mostly building servers. Every later chapter on security and production hardening assumes you have a working mental model of what code sits on the other side of a tool call — this is that code, and you built it yourself.
