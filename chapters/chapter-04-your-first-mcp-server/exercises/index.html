Chapter 4 Exercises ~30 min

Exercises: Your First MCP Server

Extend the notes server from the lesson. Four tasks, two of them production-gear.

How to run these 
pip install "mcp[cli]"
cd chapters/chapter-04-your-first-mcp-server/exercises
python starter.py   # fill in the TODOs first
Compare against solution.py once you're done or stuck. The solution was verified end-to-end against the official SDK's in-memory Client — see the lesson's Build section for the test pattern to reuse here.
starter.py solution.py (reference)

1 Delete a note

Add a delete_note(title: str) -> str tool. Raise ValueError if the title doesn't exist — don't fail silently.

2 Search notes

Add a search_notes(query: str) -> list[str] tool that returns titles of notes whose body contains the query, case-insensitive.

3 (Production-gear) Cap the body length

save_note currently accepts input of any size. Add a 10,000-character limit and raise a clear ValueError if it's exceeded. Then write a quick client call that sends 10,001 characters and confirm result.is_error is True — errors from a tool function don't raise a Python exception on the client side, they come back as a flagged result. This matters: calling code that only wraps tool calls in try/except will silently miss these failures.

4 (Production-gear) Tool or resource?

Add a note_count() -> int tool. Before you write it, decide: should this be a tool or a resource? Write a one-sentence justification as a comment. There's a defensible answer either way — the goal is to practice the reasoning, not land on one "correct" answer.

5 (Production-gear) Reject empty titles

save_note("", "some body") currently succeeds and creates a note with no name, which is impossible to reference again by title. Add validation that rejects an empty or whitespace-only title with a clear ValueError. Then decide: should delete_note and read_note also validate their title argument, or is it safe to assume it's already valid by the time those run? Justify your answer.

6 Rename a note

Add a rename_note(old_title: str, new_title: str) -> str tool. Decide what should happen if new_title already exists — overwrite silently, or raise an error? Pick one, implement it, and write a one-line comment explaining why you picked it over the alternative.
