Chapter 4 Practice Bank ~20 min

Practice Bank: Your First MCP Server

Scenario-based questions grounded in real operational, product, and compliance situations — not just "write a tool."

On this page 1. Tool design judgment 2. Operational reasoning

1. Tool design judgment

Scenario

The one-tool-does-everything proposal

A teammate proposes replacing your five note-related tools (save_note, list_notes, delete_note, search_notes, note_count) with one tool, notes_action(action: str, **kwargs), to "keep the catalog small." What do you say?

Consider: catalog size vs. model tool-selection accuracy; what a single loosely-typed kwargs parameter does to schema validation; whether five well-named tools or one vague one is easier for a model to use correctly. There isn't one universal right answer — a defensible response weighs the trade-off explicitly rather than picking a side reflexively.

Scenario

The compliance ask

Legal asks: "can we prove which notes were read, by whom, and when?" Your current read_note resource has no logging. What has to change, and where does that change belong — inside the resource function, or somewhere else in the stack?

2. Operational reasoning

Scenario

The silent failure

A user reports that saving a very long note "does nothing" — no error shown in their chat UI, the note just isn't there afterward. Given that ValueErrors from a tool come back as result.is_error = True rather than a raised exception, what's your hypothesis for where in the host/client stack this could be getting swallowed?

Scenario

The restart

Your notes server has been running for three weeks and just got restarted for a routine deploy. Every note is gone. Was this a bug? What would you change about the architecture — and what would you NOT change, because it's out of scope for a "first MCP server" chapter's design?

Scenario · Cost

The 40-tool catalog

Product wants to merge three internal servers (notes, bookmarks, tasks — 14 tools total) behind one host so users "only connect to one thing." Every one of those 14 tool schemas is sent to the model on every single turn. Estimate, in plain terms, why this is a real recurring cost, not a one-time integration cost, and what you'd measure before approving the merge.

Scenario · Support

The support ticket

A user says: "I told the assistant to delete my 'todo' note and it said it worked, but the note is still there." Given delete_note from the exercises, list three different root causes consistent with this symptom — at least one should be a bug in your tool, and at least one should be a problem elsewhere in the host/client stack that your tool can't fix.
