Chapter 4 Project ~45 min · Level 1, Guided

Build a Bookmarks MCP Server

A portfolio-worthy first project: a server that outlives the chapter's in-memory example by actually persisting data to disk.

The lesson's notes server loses everything on restart — fine for learning, not fine for anything real. This project fixes that: build an MCP server that manages bookmarks (URL, title, tags) backed by a JSON file, so your bookmarks survive a restart the way a real tool integration needs to.

starter.py solution.py (reference)

Build it

Implement add_bookmark, list_bookmarks, and a bookmark://{encoded_url} resource in starter.py. Test with the in-memory Client pattern from the lesson. Watch for the URI-template gotcha called out in the TODOs — a bare URL breaks MCP's own template matching because it contains ://; the reference solution shows the percent-encoding fix, confirmed against the real SDK while writing this project.

Verification 
python -c "
import asyncio
from mcp import Client
from solution import mcp, bookmark_resource_uri

async def main():
    async with Client(mcp) as client:
        await client.call_tool('add_bookmark', {
            'url': 'https://modelcontextprotocol.io',
            'title': 'MCP Docs',
            'tags': ['mcp', 'docs'],
        })
        print(await client.call_tool('list_bookmarks', {}))
        r = await client.read_resource(bookmark_resource_uri('https://modelcontextprotocol.io'))
        print(r.contents[0].text)

asyncio.run(main())
"
Expect the tool list, then MCP Docs — tags: mcp, docs.
Extension challenge Add a remove_bookmark(url: str) -> str tool, and think through (comment, don't necessarily fix) the race condition noted in the solution: what happens if two clients call add_bookmark at nearly the same time against the same JSON file?

Why this project matters

Every real MCP server eventually has to answer "where does the data actually live, and what happens when the process restarts?" This project makes you answer that question explicitly instead of leaving it implicit — and the URI-encoding bug you'll hit along the way is a genuinely common gotcha, not a contrived teaching example.
