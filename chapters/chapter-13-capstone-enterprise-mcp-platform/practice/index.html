Alternate Capstone Scenarios

The lesson's Northshore Regional Health scenario is the primary capstone. These are alternates — use one for additional practice, to compare against a study group's different submission, or if your instructor assigns a specific domain.

Domain · Banking

Meridian Trust — fraud investigation copilot

A regional bank wants an assistant for fraud investigators: look up transaction history, pull customer risk scores from a third-party service, and draft suspicious-activity report summaries. Compliance's specific worry: an investigator's assistant must never be able to actually move money or change account status, even if manipulated — investigation tools and transaction tools must be architecturally incapable of being confused for one another.

Domain · Insurance

Coastal Mutual — claims processing assistant

An insurer wants an assistant that helps adjusters review claims, pull policy documents, and check submitted photos/documents against fraud-indicator patterns. Compliance's specific worry: claimant-submitted documents (the definition of untrusted content) are the primary input, and the assistant must never let a submitted document influence which policy limits or payout amounts get suggested, only factual claim details.

Domain · Enterprise IT

Vantage Systems — incident response copilot

An enterprise IT team wants an assistant that can query monitoring systems, pull runbooks, and post updates to an incident channel during outages. Compliance's specific worry: this assistant will have access to internal architecture details and credentials context during incidents — a compromised or manipulated instance during an active incident is a uniquely bad time for it to leak information or take unauthorized action.

Domain · Retail

Brightline Retail — customer support automation

A retailer wants an assistant that can look up order status, process returns within policy limits, and answer product questions using externally-sourced product documentation. Compliance's specific worry: the assistant must never approve a return outside policy limits (dollar amount, time window) regardless of how a customer's message is phrased — this is squarely a least-privilege and confirmation-threshold design problem.

Using an alternate scenario Follow the same deliverables checklist and rubric from the main capstone — only the domain and specific compliance concern change. Each scenario above is deliberately built around a different one of this course's Module 5 security patterns (fraud/least-privilege, untrusted-content/injection, access-during-incident, policy-limit enforcement) so no two scenarios exercise identical reasoning.
