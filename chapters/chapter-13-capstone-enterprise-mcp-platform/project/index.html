Chapter 13 Capstone Submission Level 4 · Architecture Challenge

Submit the Capstone

Architecture document, ADRs, and a working extension of the reference skeleton — the full submission this course builds to.

starter.py is the tested reference skeleton from the lesson, with three documented gaps. solution.py closes one of them (acting on injection flags via a confirmation requirement) as a worked example of what "closing a gap" looks like in real code — it is not "the" correct capstone answer. Your submission should close gaps in ways that match your own architecture decisions, documented in your own ADRs.

starter.py solution.py (one worked example, not the answer key) adr-template.md

What to submit

  1. The full architecture document (all sections from the lesson's "what to produce" list).
  2. At least 3 ADRs, in the format the lesson specifies.
  3. A working code extension closing at least one documented gap in the reference skeleton, with output demonstrating it works — the same "run it and show the real output" discipline every chapter in this course has used.
Verify your extension actually changed something Run your extended code against BOTH the "should be blocked/flagged" case and the "should succeed normally" case, and show both outputs — a fix that only demonstrates the success case doesn't prove anything, per the discipline established as far back as Chapter 6's health-check project.
Self-check before submitting Re-read the lesson's rubric table and "common mistakes" list. Would a reviewer using that rubric find your submission complete?

Why this project matters

This is the synthesis of everything: the tested-code discipline from Chapter 4 onward, the layered security thinking from Module 5, the observability and hardening practices from Module 6, and the architecture-level judgment this course has been building toward in every "production scenario" section. If you can produce this submission, you can defend an MCP architecture decision in a real design review — which was the whole point.
