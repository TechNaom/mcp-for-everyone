Chapter 13 Deliverables ~4–8 hours total

Capstone Deliverables Checklist

The capstone broken into sequenced, concrete tasks — work through them in order, since later ones depend on earlier decisions.

Before you start Read the full scenario in the lesson. Run the reference skeleton in project/starter.py to see the pattern working before you extend it — don't design in the abstract without touching the real code first.

1 Write the problem statement (0.5–1 page)

Restate Northshore's problem in your own words. Name the specific compliance concern explicitly — not "security is important" but the exact injection-via-external-document scenario described.

2 Define requirements

Functional requirements (what the system does) and non-functional requirements (availability, latency, auditability) — separate sections, per the lesson's "what to produce" list.

3 Design server boundaries

Decide how many MCP servers, and why — this becomes your first ADR. Extend the reference skeleton's two-server split (patient records, external docs) or justify a different boundary.

4 (Production-gear) Design the permission scope taxonomy

Per Chapter 9's senior interview question on scope design — group by resource and risk, not one scope per tool or one scope for everything. This becomes your second ADR.

5 (Production-gear) Design the layered injection defense

Specify all the layers from Chapter 10's cheat sheet as they apply here — scanning, least privilege, confirmation, structural separation. This becomes your third ADR.

6 Design the observability strategy

Specify exactly what gets logged so "who accessed which patient's data, when" is answerable — reference Chapter 11's structured logging pattern concretely, don't describe logging in the abstract.

7 Write the data flow trace

Walk one real request (a clinician requesting a patient summary) through every component, end to end.

8 (Production-gear) Extend the reference skeleton

In project/starter.py, close at least one of the gaps named in the lesson (act on injection flags, real audit logging, or authentication behind scopes) — a working code extension, not just a written description.

9 Write failure handling, deployment, and cost sections

Per the lesson's "what to produce" list — brief but concrete.

10 Assemble and self-review against the rubric

Check your submission against the lesson's rubric table and "common mistakes" list before considering it done.
