Chapter 9 Exercises ~25 min

Exercises: Permissions, Scopes & Sandboxing

Extend the scope-checking pattern with a distinct delete scope, and build a proper test harness for it.

How to run these 
pip install "mcp[cli]"
cd chapters/chapter-09-permissions-scopes-sandboxing/exercises
python solution.py   # or fill starter.py first
starter.py solution.py (reference)

1 Add a delete scope

Implement delete_note requiring notes:delete, distinct from notes:write, per TODO 1.

2 (Production-gear) Build a safe test helper

Implement try_call per TODO 2, using try/finally to guarantee the scope resets even if the call raises. Why does this matter for a test suite that runs many scope combinations in sequence?

3 (Production-gear) Test the scope boundary

Confirm write-only access can save but not delete, per TODO 3.

4 (Production-gear) Test the negative space

Write a test confirming a caller with ONLY notes:read can list notes but can call neither save_note nor delete_note. This is the "deny by default" case — the most important one to test, per this chapter's senior interview question on testing permission systems.

5 Add a fourth scope

Add a search_notes(query: str) -> list[str] tool. Should it require notes:read, a new scope, or no scope at all? Justify your choice.

6 (Production-gear) Find the missing check

Add a fifth tool WITHOUT a @require_scope decorator by mistake (simulate forgetting one). Write a test that would catch this specific mistake automatically — a tool shipped with no scope check at all — before it reaches production.
