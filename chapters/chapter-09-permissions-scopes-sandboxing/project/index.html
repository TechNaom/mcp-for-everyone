Chapter 9 Project ~35 min · Level 2, Assisted

Build a Permission Audit Tool

A script that catches "someone forgot the @require_scope decorator" automatically — the practice bank's exact regression scenario, solved with code instead of hoping a reviewer notices.

The require_scope decorator in this chapter's lesson and exercises sets a small marker, wrapper._required_scope = scope, specifically so tooling like this project can introspect a server's tools and confirm every single one actually has a scope check — without relying on someone remembering to look.

starter.py solution.py (reference)

Build it

Implement audit_scopes (check each named tool for the _required_scope marker) and print_report (a clear PASS/FAIL summary). Then prove your audit tool actually catches a missing check by testing it against a deliberately unscoped fake tool.

Verification 
python solution.py
Expect: 
PASS: all tools have scope checks.

Re-running against a module with a deliberately missing check:
FAIL: 1 tool(s) with NO scope check:
  - delete_note
Extension challenge Turn this into something CI could actually run: make the script exit with a non-zero status code when any tool is unscoped, so it could gate a deploy pipeline the way a real security check would.

Why this project matters

This chapter's own practice bank asked "what test would catch a regression where someone forgot a scope check?" — this project is that test, built and proven against a real, injected failure. A security control that isn't verified by tooling is a security control that eventually silently regresses.
