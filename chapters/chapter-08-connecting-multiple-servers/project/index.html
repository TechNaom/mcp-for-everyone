Chapter 8 Project ~40 min · Level 2, Assisted

Build a Two-Server CLI Host

Extend Chapter 7's CLI host to connect the notes AND bookmarks servers simultaneously, with namespaced commands.

Commands now look like notes.save_note ... or bookmarks.add_bookmark ... — the namespace prefix from this chapter's lesson, made real. Building this surfaced a genuine limitation worth knowing about: a naive CLI argument parser only produces strings, but add_bookmark's tags argument requires a list. The reference solution's parse_line handles bracketed values like tags=[mcp,docs] as lists — a small, real example of client code needing to match a tool's actual schema, not just pass strings and hope.

starter.py solution.py (reference)

Build it

Implement MultiServerHost.connect (namespace a server's tools into the shared catalog) and run_line (parse, look up the namespaced command, route to the right client, check is_error). Then wire up both servers in main().

Verification 
printf 'notes.save_note title="todo" body="buy milk"\nbookmarks.add_bookmark url="https://modelcontextprotocol.io" title="MCP Docs" tags=[mcp,docs]\nbookmarks.list_bookmarks\nquit\n' | python solution.py
Expect both commands to succeed against their respective servers, with bookmarks.list_bookmarks showing the saved URL.
Extension challenge Add a third server (reuse Chapter 8's exercise servers, which deliberately collide on search) and confirm your host handles the collision correctly via namespacing — try calling both notes-service.search and docs-service.search and confirm they return different results.

Why this project matters

This is the first project in the course connecting two genuinely different, independently-built servers to one host at once — the architecture Chapter 2 described in the abstract, now something you've actually run.
