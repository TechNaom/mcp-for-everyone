Chapter 8 Practice Bank ~20 min

Practice Bank: Connecting Multiple Servers to One Agent

Multi-server judgment calls beyond the naming-collision mechanics.

Scenario · Support

The regression nobody flagged

Following this chapter's production scenario, what would you add to a deploy pipeline (not just a test suite) to make a new collision impossible to ship silently?

Scenario · Product

The user-visible tool name

If a host's UI shows users which tool the assistant used (e.g., "used notes-service.search"), is the namespaced name a UX problem? How would you present it more cleanly without losing the disambiguation?

Scenario · Cost

The catalog re-merge

A host with 10 connected servers re-runs the full namespaced merge on every new conversation. What's the cost of this at scale, and how does it relate to the catalog-caching discussion from Chapter 7?

Scenario · Debugging

The routing bug

A namespaced catalog looks correct, but calling docs-service.search actually invokes notes-service's tool. What's the most likely bug in the routing code, based on this chapter's call_namespaced pattern?

Scenario · Operations

The server that goes away mid-session

One of three connected servers becomes unreachable partway through a conversation. Should the host's merged catalog immediately drop that server's tools, or leave them (and fail individual calls)? Justify either answer.

Scenario · Eval

The evaluation dataset that hides the bug

A team's tool-selection eval dataset was built before a second server with a colliding name was added, so no test case ever exercises the ambiguous tool. What does this suggest about how eval datasets need to evolve alongside a growing multi-server host?
