Chapter 6 Exercises ~25 min

Exercises: Transports

Run the notes server over the network, in both session-based and stateless modes, and see the difference yourself.

How to run these 
pip install "mcp[cli]"
cd chapters/chapter-06-transports/exercises

# terminal 1
python solution.py

# terminal 2
python client_check.py
Then repeat both with --stateless appended to compare.
starter.py solution.py (reference) client_check.py

1 Run it over HTTP, session-based

Complete TODO 1 in starter.py: run the server over Streamable HTTP on port 8767 with default settings. Confirm client_check.py can reach it.

2 Add the stateless variant

Complete TODO 2: add a --stateless branch running on port 8768 with stateless_http=True.

3 (Production-gear) Reproduce the 400

With the session-based server running, use curl directly (not client_check.py) to send a raw tools/list request with no session header. Confirm you get the same 400 the lesson showed. Then repeat against the stateless server on port 8768 and confirm it succeeds.

4 (Production-gear) Inspect the session header

Look at the 400 response's headers from Task 3. It includes an mcp-session-id the server generated even though it rejected the request. What would a well-behaved client do with that header on its next attempt?

5 (Production-gear) Pick a transport for a real scenario

Your team is building a coding-agent plugin that runs entirely on a developer's laptop, launched by their IDE. Which transport, and why? Now suppose the same capability needs to be offered as a hosted service to the whole company — does the answer change?

6 Compare startup complexity

Count the extra decisions/config Streamable HTTP required that stdio didn't (host, port, session mode). Is this complexity ever worth paying for a purely local, single-user tool? Justify either answer.
