Chapter 6 Practice Bank ~20 min

Practice Bank: Transports

Deployment and operational judgment for transport choices.

Scenario · Operations

The mystery session errors

A team reports intermittent "session not found" errors from their Streamable HTTP server after a routine deploy that added a second instance. Using this chapter's production scenario, what's your first hypothesis, and what would you check to confirm it?

Scenario · Cost

The always-on server

Compare the operating cost of a stdio-based tool (only runs while a client has it open) versus a Streamable HTTP server (must run continuously to be reachable). What does this mean for a rarely-used internal tool?

Scenario · Security

The exposed port

A Streamable HTTP server was deployed with the port open to the public internet "temporarily," for testing. Independent of authentication (Module 5 territory), what transport-level exposure does this create that a stdio server never would?

Scenario · Debugging

The client that "can't connect"

A developer reports their client can't reach a Streamable HTTP server. List three transport-layer things you'd check before assuming it's an MCP-specific bug (hint: most of this isn't MCP-specific at all).

Scenario · Support

The SDK-version mismatch

A colleague on an older SDK version says stateless_http isn't a recognized parameter for them. What does this suggest about how you should present SDK-specific defaults like this one in internal documentation — as permanent facts, or as something to verify per-version?

Scenario · Eval

The transport-agnostic test suite

Your team wants one test suite that runs against both a stdio and a Streamable HTTP instance of the same server, to make sure behavior is identical either way. What's one thing that's easy to test identically across both, and one thing that genuinely differs and needs separate test logic?
