Chapter 6 Project ~30 min · Level 1, Guided

Build a Health-Check Probe

The kind of script an ops team would actually wire into a load balancer or monitoring system for a Streamable HTTP MCP server.

"Is the port open" isn't the same as "is the server healthy" — a process can accept TCP connections while its MCP-handling code is deadlocked. This project checks the thing that actually matters: can this server list and call a tool within a reasonable time.

starter.py solution.py (reference)

Build it

Implement check_server(url): connect, call list_tools(), treat zero tools as unhealthy, then call the first tool with a timeout and treat a timeout as unhealthy. The function must never raise — a health check that crashes the thing calling it is worse than one that just reports unhealthy.

Verification 
# terminal 1
python ../exercises/solution.py

# terminal 2
python solution.py http://127.0.0.1:8767/mcp
# expect: HEALTHY, exit code 0

# stop terminal 1, then:
python solution.py http://127.0.0.1:8767/mcp
# expect: UNHEALTHY (with a reason printed), exit code 1
Extension challenge Add a --json flag that prints the result as {"healthy": true, "checked_at": "...", "tool_count": N} instead of plain text — the format a real monitoring system would actually want to parse.

Why this project matters

Chapter 6's production scenario was caught by someone actually testing wire behavior, not by a dashboard showing green. A real health check that exercises an actual tool call — not just a TCP connection — is exactly the kind of thing that would have caught that class of problem before it hit users.
