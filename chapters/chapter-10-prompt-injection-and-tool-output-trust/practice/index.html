Chapter 10 Practice Bank ~20 min

Practice Bank: Prompt Injection & Tool-Output Trust

Risk judgment for a threat that has no complete technical solution.

Scenario · Security

The false sense of security

A team ships a regex-based injection scanner and marks the "prompt injection" risk item as "mitigated" in their security review. What's wrong with this framing, and what would a more accurate status look like?

Scenario · Product

The confirmation fatigue problem

A host requires human confirmation for every tool call that touches externally-fetched content, per this chapter's layered defense. Users start reflexively clicking "confirm" without reading, defeating the purpose. What UX change would help without abandoning the confirmation requirement entirely?

Scenario · Support

The support ticket about a weird summary

A user reports a document summary "left out something important." Given this chapter's production scenario, what would you check first, before assuming it's a normal summarization-quality issue?

Scenario · Compliance

The regulator's question

A compliance team asks whether your AI system is "protected against prompt injection." How do you answer honestly, given this chapter's "why detection alone isn't enough" section, without either overclaiming safety or sounding like the system has no protections at all?

Scenario · Cost

The expensive confirmation step

Requiring human confirmation for every consequential action after processing untrusted content slows down an otherwise-automated workflow significantly. How would you decide which actions genuinely need this friction versus which are low-risk enough to automate?

Scenario · Operations

The third-party server you don't control

Your host connects to a partner's MCP server whose tool outputs you can't audit or modify. What layers from this chapter's defense strategy can you still apply, given you don't control the source of the potentially-injected content?
