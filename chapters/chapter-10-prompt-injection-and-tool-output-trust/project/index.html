Chapter 10 Project ~35 min · Level 2, Assisted

Build a Tool-Output Firewall

A reusable wrapper that scans, logs, and flags every tool call — the layered defense from the lesson, packaged as something a real host could actually use.

This project reuses Chapter 10's exercises module — and building it surfaced a real, general bug worth knowing about: importing a Python file that unconditionally calls asyncio.run() at the top level crashes if you're already inside a running event loop (exactly what happens when a firewall wraps a live async tool call). The fix, applied here and retroactively across every earlier chapter with the same pattern, is a simple if __name__ == "__main__": guard.

starter.py solution.py (reference)

Build it

Implement ContentFirewall.call: call the underlying tool, scan the result, log every call (not just flagged ones), and return a FirewallVerdict the calling host can act on.

Verification 
python solution.py
Expect all three demo pages processed, with the malicious and sneaky pages both showing confirm=True, and a full log printed at the end showing all three calls — including the clean one.
Extension challenge Combine this with Chapter 9's require_scope decorator: make ContentFirewall refuse to even attempt a tool call if the current caller lacks a content:fetch scope, demonstrating both defense layers working together in one wrapper.

Why this project matters

A real host doesn't call tools directly the way every earlier chapter's tests did — it calls them through exactly this kind of wrapper, so scanning and logging happen automatically for every call, not as an opt-in step someone has to remember. This is the shape of code that actually ships in a production host.
