Chapter 10 Exercises ~25 min

Exercises: Prompt Injection & Tool-Output Trust

Extend the scanner, then build the layered "flag, don't silently allow or block" pattern from the lesson.

How to run these 
pip install "mcp[cli]"
cd chapters/chapter-10-prompt-injection-and-tool-output-trust/exercises
python solution.py   # or fill starter.py first
starter.py solution.py (reference)

1 Catch the sneaky page

Add a pattern that catches the "sneaky" page's phrasing without false-positiving on the benign recipe page, per TODO 1.

2 (Production-gear) Wrap fetch + scan

Implement fetch_page_safely per TODO 2, returning both the content and the scan hits so calling code decides what to do rather than the tool making that decision silently.

3 (Production-gear) Wire up the confirmation policy

Implement should_require_confirmation per TODO 3.

4 (Production-gear) Combine with Chapter 9's scopes

Import Chapter 9's require_scope pattern and apply it to a hypothetical delete_all_notes tool. Even if the malicious page's injected instruction "worked" on a model, what scope would need to be present in the current context for the instruction to cause real harm? Write this reasoning as a comment.

5 Find a pattern your scanner misses

Write a new fake "page" containing an injection attempt phrased so your current patterns (including your Task 1 addition) don't catch it. This is the point of the exercise — confirm for yourself that the scanner is genuinely incomplete, not just told so.

6 (Production-gear) Log every scan result

Modify fetch_page_safely to print a log line for every call (URL, hit count, timestamp) regardless of outcome — the beginning of the audit trail this chapter's architect interview question said was a prerequisite for incident response.
